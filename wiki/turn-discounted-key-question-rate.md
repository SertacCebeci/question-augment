# Turn-discounted key question rate

> Score a clarification dialogue the way search ranking scores a result
> list: credit a question only the first time it covers a missing piece of
> information, and discount that credit the later it comes.

## Definition / Mechanism

Fang et al. (2026) define Turn-discounted
Key Question Rate (TKQR) for ClarifyCodeBench, a code-generation benchmark
where each task carries $K$ annotated key clarification questions whose
answers were deleted from an otherwise complete requirement. Over a
dialogue of $n$ turns before the model stops asking and produces code,
build a hit sequence $h_i \in \{0,1\}$: $h_i=1$ the first time turn $i$
asks a previously uncovered key question (repeats score nothing),
$h_i=0$ otherwise. Discounted gain is
$\mathrm{DCG}_n=\sum_{i=1}^n h_i/\log_2(i+1)$, normalized against the
ideal ordering that covers all $K$ key questions in the first
$\min(n,K)$ turns, $\mathrm{IDCG}_n=\sum_{i=1}^{\min(n,K)}1/\log_2(i+1)$.
$\mathrm{TKQR}=\mathrm{DCG}_n/\mathrm{IDCG}_n \in [0,1]$, rising when key
questions are covered earlier and falling when they are delayed or
crowded out by non-key questions.[^c1]

## Why it matters

TKQR scores this wiki's stall-2 question — which axis first — per
dialogue, not just at the endpoint: two agents that eventually cover the
same key questions are scored apart if one covers them in the first turns
and the other in the last. On six LLMs the scores are low and close
together — the best model, DeepSeek-V3.2, reaches TKQR 0.30, and most
others stay below 0.30 — registering a shared ordering failure on top of
the shared under-asking already reported by [[clarification-benchmarks]].[^c2]

## Transfer

| | Home field | Here |
|---|---|---|
| Formalism | Information retrieval: normalized discounted cumulative gain (nDCG) scores a ranked result list against graded relevance judgments | ClarifyCodeBench scores a clarification dialogue's turn order against a fixed, per-task set of annotated key questions |
| What survives | Log-discounted credit for an item appearing earlier, and normalization against an ideal ordering so scores compare across items with different totals ($K$) | Both carry over unchanged: the same discount and $\mathrm{IDCG}$ normalization are applied to dialogue turns exactly as nDCG applies them to ranked documents |
| What does not | Relevance judgments are typically graded and independent of the ranker's own behavior; the ranked list has a fixed, known length before scoring | Relevance here is binary and decided by an LLM-as-judge match to the annotated question rather than a human label, and $n$ (the number of turns) is the model's own choice rather than a fixed pre-existing list — so a model that asks one extra non-key question inflates $n$ without changing the numerator, lowering TKQR for a reason nDCG never had to price |
[^c3]

## Limits

- Defined and evaluated on one benchmark (419 tasks built by
  deletion-only editing of LiveCodeBench v6) with $K \le 3$ per task;
  whether the discount and normalization behave the same with more key
  questions, or on naturally occurring rather than injected [[efe-planning-as-variational-inference|ambiguity]], is
  untested.
- The key-question match is decided by an LLM-as-judge (GPT-4o, three
  samples, majority vote), not a human rater, so TKQR inherits that
  judge's error rate as measurement noise on top of the model's own
  behavior.
