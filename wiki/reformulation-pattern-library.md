# Reformulation pattern library

> A query is not reformulated freely; it is first classified into a named transformation, and only that transformation is generated.

## Definition / Mechanism

Most LLM-based query reformulation prompts a model to rewrite a query
directly and treats the model as a black box: it produces new text
without stating what transformation it applied or why.
ReFormeR (2026) inserts a discrete decision before
generation. Given training pairs $(q_i,\tilde q_i)$ of an original
query and an empirically stronger reformulation of it (queries drawn
from a corpus of reformulations that reach perfect retrieval
effectiveness, MRR=1, on a held-out split), an LLM is prompted once
per pair to describe the transformation it embodies, and the resulting
descriptions are clustered into a small set of non-overlapping pattern
labels $\mathcal P=\{p_1,\dots,p_M\}$: "we first elicit concise
reformulation patterns from pairs of initial queries and empirically
stronger reformulations, consolidate these patterns into a small
library of reusable reformulation patterns, and then choose the most
appropriate pattern for a new query in light of retrieval context.
Only after a pattern is selected do we generate the reformulation
under that pattern's constraints."
[^c1]

The induction step is explicit: "We obtain an induction mapping 𝑔
that assigns each pair to one pattern... by eliciting a concise
description of the reformulation with an LLM for each pair and
clustering the resulting representations to produce non-overlapping
groups."
[^c2]

At inference time a trained selector $\pi_\theta(p\mid q, D_k(q))$
takes a new query and its top-$k$ retrieved context and returns a
distribution over the fixed pattern set; a conditional generator then
produces the reformulation *under the selected pattern's constraints*,
and the final retrieval query concatenates the original query with
this constrained reformulation. The mined library names ten recurring
transformations: "Clarify Intent, Clarify Subject, Conceptual Shift,
Contextual Expansion, Contextual Restriction, Generalization, Location
Specification, Purpose Specification, Semantic Clarification, Temporal
Adjustment."
[^c3]

The pattern is not a hand-authored taxonomy: it is induced bottom-up
from what successful reformulations of real queries actually did, then
reused as a closed label set a selector can be trained on.

## Why it matters

The pattern is the load-bearing move that [[compcqr]] and open-ended
LLM reformulation both skip: rather than generating one best-guess
rewrite or enumerating many uncommitted variants, ReFormeR commits to
*which kind* of transformation a query needs before any text is
generated, making the reformulation policy an inspectable, reusable
object instead of an artifact buried in a prompt. Against classical
feedback (RM3, Rocchio) and unconstrained LLM reformulation (GenQR,
GenQREnsemble) on TREC DL 2019, DL 2020 and DL Hard: "ReFormeR
delivers consistent and meaningful improvements over both classical
feedback and generative baselines. Against traditional methods such as
RM3 and Rocchio, ReFormeR achieves up to 16% higher nDCG@10 on TREC DL
2020 and about 26-34% higher mAP@1k on DL Hard."
[^c4]

The gain concentrates on the harder, sparser DL Hard queries, and
pattern-constrained reformulations also compose with context-aware
generators (QA-Expand, Query2Doc, MUGI), improving on top of each when
concatenated into their prompts.

## Limits

The pattern library is mined from one dataset (MS MARCO query pairs
selected for perfect retrieval effectiveness) with one LLM
(Qwen2.5-72B for induction, Qwen2.5-7B-Instruct for selection and
generation); whether the same ten patterns, or the same gain from
naming them, transfers to another retriever, another query
distribution, or a non-IR question-asking setting is untested. The
selector is trained on labels the induction step itself produced, so
its accuracy is bounded by how cleanly that clustering separated true
transformation types — a circularity the paper does not audit
independently. The reformulation is still generated by an LLM once a
pattern is chosen; the pattern constrains what the model is asked to
do, not what it is capable of producing, so drift within a pattern
remains possible. `[?]` — unverified: the paper reports one seed/run
per configuration, with no variance across repeated pattern-induction
or training runs.
