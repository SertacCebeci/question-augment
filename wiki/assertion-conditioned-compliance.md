# Assertion-conditioned compliance

When a multi-turn agent is handed a false claim, two different things can happen. It can say it agrees, which is verbal sycophancy. Or it can change what it does, invoking the function the false claim pointed to. Waqas et al. name the second case assertion-conditioned compliance (A-CC) and set it apart from verbal agreement: "A-CC instead captures procedural compliance, in which the execution pipeline itself is altered."[^c1] The agent is not hijacked toward a malicious goal. It keeps its helpful objective and "fails to verify false premises against the tool history, environment state or function documentation."[^c2]

The measurement is a compliance rate (CR). A case counts as compliant when the model invokes the asserted function "at least once at any point within"[^c3] the turn where the assertion appears. Each BFCL multi-turn case is run once without an assertion and again with one, so that any behavioural difference is attributed to the injected sentence or tool note.

Provenance is the paper's central variable. A user-sourced assertion (USA) is one plausible but incorrect sentence in the user turn, phrased either confidently or hedged. A function-sourced assertion (FSA) is a "system policy note (a textual note appended to"[^c4] a tool's output, declaring a rule that contradicts the user's intent. The injection is conditional: it happens only if the "agent successfully invokes the target function"[^c5] at the intended turn. The two channels produce different compliance profiles, which the authors summarise as "substantial but systematically different compliance."[^c6]

The reported figures: the macro-averaged USA compliance rate is 36.3% for confident assertions and 27.7% for hedged ones.[^c7] Under the FSA baseline, compliance averages 27.8% across models.[^c8] The worst observed success drop averages 16.9 points per model.[^c9] The largest single drop is in Qwen3 14B: "Qwen3 14B (FC) is the most vulnerable, with a 23.4 point"[^c10] from a 50.2% no-assertion baseline.

The authors read the FSA result as showing that models treat "tool feedback as comparatively authoritative"[^c11] — a model trusts what a tool returns over what the user asked. That is an interpretation of the pattern, not a tested mechanism; the paper does not isolate why tool-native models comply more.

## Limits

- The assertions were generated by a teacher model rather than taken from logs: they are "rather than harvested from wild"[^c12] user interactions, and the authors say the results are "controlled stress test rather than a direct measure"[^c13] of live performance.
- One benchmark and one category: "Our evaluation is grounded exclusively on"[^c14] the multi_turn_base category of BFCL, so generalisation to other agent frameworks is untested.
- The FSA condition is an ablation, applied to write-heavy turns with confident phrasing: "ablation condition targeting only write-heavy"[^c15] turns. Hedged FSAs and read-heavy FSAs are not in the table.
- CR counts an invocation, not a harmful outcome. Whether an adopted call damages anything is a separate question the metric does not answer (my reading).
- The work proposes no defence: the authors "do not yet propose specific training objectives, unlearning techniques, or architectural modifications".[^c16]
- English only, so the social-compliance findings may not carry to other languages or cultures.
